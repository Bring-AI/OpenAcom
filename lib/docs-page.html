快速开始

npm install -g github:wwy155/openacom   # Node ≥ 22.5

openacom list                # 四家 agent 会话混合列表（模糊搜索，默认 top30）
openacom read <sessionId>    # 读任意会话最近对话
openacom send <sessionId> "消息" --require-read   # 带已读回执发送
openacom web                 # 本页 + 收件箱面板

CLI 命令

命令说明
list [关键词...] [--agent A] [--limit N]zcode / claude / codex / opencode 四家会话混合列表，多词 AND 模糊搜索（匹配 agent/ID/标题/工作区），默认 top30
read <sessionId> [--last N]读任意会话最近回合，系统噪声已过滤，自动跨四家匹配 id
send <消息>在全新 zcode 会话执行（默认异步），新会话自动出现在桌面任务列表
send <sessionId> <消息>向指定会话注入真实用户回合。zcode 走桌面 CDP（失败直接报错）；opencode 直接 steer 原会话并实时流式；--wait 阻塞等回复，--no-wait/--no-desktop 显式降级
send ... --require-read [--ack-timeout ms]已读回执模式：未回执自动重发（共 3 次），仍无回执判 failed
inbox [--status S] [--json]查看追踪消息及状态：sent 待回执 / read 已读 / failed 判死
ack <messageId>手动把一条追踪消息标记为已读
hooks查看已配置的事件钩子
web [port]启动收件箱面板 + 本文档（默认 127.0.0.1:9339）
oc-serve / oc-attach [目录]opencode 共享 server：预热 / 一步打开实时 TUI
mcp / mcp-http [port]stdio / streamable-HTTP MCP 服务器
relay ... / terminal ...分布式消息（hub/node/send/status）与托管终端，见下方分布式节

MCP 工具

stdio 服务器暴露的基础工具（任何 MCP 客户端可接）：

工具说明
list_sessions会话列表，支持 query 模糊搜索 + limit（默认30）
read_session读会话最近 last 个回合
send_message必填 from/to（agent:sessionId 地址）。默认 fire-and-forget；wait:true 阻塞等回复；requireRead:true 开启已读回执；to:"zcode:new" 发新会话
get_paths各 agent 存储路径与 CLI 位置（诊断用）
ack_message 回执目标 agent 处理消息后标记已读（id 在消息页脚）
inbox 回执查询追踪消息状态（可按 status 过滤）

配置 AGENTRELAY_URL + AGENTRELAY_TOKEN 环境变量后额外启用分布式三件套 relay_nodes / relay_send / relay_status。四个本地基础工具从不依赖 Hub。

已读回执语义

openacom send sess_x "部署状态如何？" --require-read
→ READ (attempt 1/3)          # 对方已确认
openacom send sess_x "紧急…" --require-read --ack-timeout 30000
→ FAILED after 3 attempts     # 3 次无回执，如实报错
  • 消息尾附回执单：[read-receipt] … ack_message(id="…") 或回复包含 ACK-<id>
  • 两条确认通道：工具调用（目标 MCP 需 ≥0.10.0 并重连）或 回复 token（旧版 MCP 也能用）
  • 每次尝试等待 --ack-timeout（默认 90s）→ 超时自动重发 → 共 3 次 → 判 failed
  • 记录存于 ~/.openacom/inbox.sqlite；投递失败也计入次数
  • 注意：requireRead 在调用进程内等待回执（最坏 ~3×超时），调用方 MCP 超时要留够

Hooks 事件

在 ~/.openacom/hooks.json 配置，回执生命周期每到一个节点就触发对应命令 （事件 JSON 写入命令 stdin；AGENTRELAY_EVENT / AGENTRELAY_MESSAGE_ID 在环境变量里；完全异步，钩子失败只记 logs/hooks.log，绝不影响投递）：

事件触发时机
message.created追踪消息创建（尚未投递）
message.sent一次投递完成（attempts 更新）
message.read收到回执（工具 ack 或回复 token）
message.failed3 次尝试后仍未回执，判死
{
  "message.read":   "node C:/scripts/notify.js",
  "message.failed": ["node C:/scripts/alert.js", "msg.exe %USERNAME% 3次未回执"]
}

事件体：{"event":"message.read","at":1695…,"message":{id,from,to,agent,sessionId,status,attempts,maxAttempts,lastError,textPreview}}

用 openacom hooks 查看当前生效配置。

Node SDK

npm install openacom（或直接 require('openacom/lib/index.js')）：

const relay = require('openacom');

relay.listSessions({ query: '组长', limit: 5 });        // 会话列表
relay.readSession('sess_…', { last: 6 });               // 读最近回合

await relay.send('sess_…', '你好', { agent: 'zcode' });  // 普通发送（等回执语义见 opts）
await relay.send(null, '新会话消息', { fresh: true });    // 全新 zcode 会话

const r = await relay.sendTracked('sess_…', '请确认部署', {
  from: 'zcode:mySession', ackTimeoutMs: 90_000, maxAttempts: 3
});
// r = { id, status: 'read'|'failed', attempts, problems? }

relay.inbox.list({ status: 'failed' });                  // 收件箱查询
relay.inbox.markRead(id);                                // 标记已读
relay.hooks.load();                                      // 当前钩子配置
await relay.web.start(9339);                             // 启动面板+文档

分布式 relay

跨机器用「带鉴权 Hub + SQLite 队列 + 各机器 Node 轮询」架构：消息持久化、幂等提交、 崩溃不重放（uncertain 状态需人工核实）。目标类型两种：terminal（托管真实 TUI 的可见输入） 和 zcode（桌面严格 CDP 投递，失败不降级）。完整配置步骤（token、SSH 转发、targets.json、 输入锁）见 GitHub README 的 「分布式通信」章节；MCP 侧配好 AGENTRELAY_URL/TOKEN 即得 relay_nodes/relay_send/relay_status 三工具。
